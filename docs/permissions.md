# «Рассвет» — матрица прав (MVP-1)

Источник правды — база (RLS + функции). Каждая клетка покрыта тестом в `supabase/tests/rls_mvp1.test.sql`.
Неактивный (без согласия) или заблокированный пользователь не видит **ничего**: все правила опираются на `private.my_role()`, которая для него возвращает пусто.

## Жёсткие правила, которые обеспечивает база, а не экран

1. **Анонимность.** Таблицу `answers` напрямую читают только админы и сам автор. Все остальные получают ленту через `answers_feed()`, где автор анонимного ответа = `null`. Обход через API невозможен.
2. **Доступ родителя к обращениям — не задним числом.** `granted_at` ставит сервер, переписать его нельзя даже с полными правами (триггер). Отозванный доступ не восстанавливается — только новая выдача с новой датой.
3. **Сообщения лидеру неизменяемы.** Правок и удалений нет: это материал на случай разбора ситуации.
4. **Автор и время — серверные.** Подделать автора ответа или обращения нельзя: триггер подставляет `auth.uid()`.
5. **Несовершеннолетний не активируется без действующего согласия.** Отзыв согласия сразу переводит подростка в `pending`.
6. **Журнал.** Смена роли или статуса, связи «родитель — ребёнок», согласия, приглашения, выдача и отзыв доступа, скрытие и удаление ответов, удаление листков и вопросов, каждое чтение обращений родителем.

## Открыто (решить до экранов)

- Помощники не отвечают на вопрос недели — сейчас так. Если должны отвечать, это одна строка в политике `answers_teen_insert`.
- Ответ лидера на анонимный ответ может раскрыть автора содержанием («Маша, спасибо…»). Это правило для админов, а не для базы.
- Смена версии согласия не деактивирует подростков, подписавших старую версию автоматически. Нужна процедура перед заменой.
- Удаление аккаунта: ответы и обращения обезличиваются (`author_id = null`), а не удаляются. Срок хранения обращений — вопрос к юристу.
